آزمون‌ها روی PostgreSQL موقت با حساب runtime محدود اجرا شدند. آزمون‌های مرتبط با ایمیلِ حذف‌شده جای خود را به قرارداد موبایل داده‌اند؛ عدد این گزارش، شمارش قابلیت‌های نسخهٔ جاری است.

موارد جدید بررسی‌شده:

- ۹ قالب معتبر، از جمله ارقام فارسی و عربی، به یک شناسه تبدیل شدند؛ ۱۱ ورودی نامعتبر، ثابت، خارجی یا دارای متن رد شدند.
- ثبت‌نام بدون ایمیل موفق شد و هیچ Outbox یا Job ارسال نساخت. API ورودی email یا ادعای phone_verified را با ۴۲۲ رد کرد.
- OpenAPI فقط ورودی phone/password را برای ورود نشان داد؛ مسیرهای ایمیلی حذف‌شده در قرارداد نبودند و ۴۰۴ دادند.
- دو قالب شماره نتوانستند حساب تکراری یا تغییر رمز حساب موجود ایجاد کنند. ثبت‌نام هم‌زمان دو قالب نیز فقط یک کاربر ساخت.
- همهٔ قالب‌ها یک bucket محدودیت ورود داشتند. شمارهٔ یکسان در سالن دیگر مستقل و در همان سالن یکتا بود.
- قالب و یکتایی در خود دیتابیس نیز بررسی شدند. شمارهٔ تماس قدیمی به‌تنهایی اجازهٔ ورود نداد.
- ابزار اتصال شماره به حساب قدیمی خارج از Tenant مشخص عمل نکرد؛ تغییر شماره نشست‌ها را لغو و تأیید قبلی شماره را پاک کرد.
- migration با دادهٔ نسخهٔ 0004 اطلاعات قدیمی را حفظ کرد و شماره یا ایمیل ساختگی نساخت. downgrade ناسازگار با حساب بدون ایمیل، بدون حذف اطلاعات rollback شد.
- آزمون‌های نشست، Cookie امن، CSRF، RBAC، جداسازی Tenant و عدم نشت رمز و شماره در لاگ همچنان موفق‌اند.

سرور پیش‌نمایش با نسخهٔ جدید روی `http://127.0.0.1:8000` اجرا شد. `scripts.check_auth_preview` از HTTP واقعی استفاده کرد و هیچ شماره، رمز یا Token را چاپ نکرد؛ ارسال پیامک و ایمیل نیز انجام نشد.

OTP، اثبات مالکیت شماره و بازیابی رمز بدون دانستن رمز فعلی هنوز پیاده نشده‌اند. زیرساخت شمارهٔ استاندارد، وضعیت تأیید و Session مشترک برای آن آماده شده است. راهنمای استفاده و مهاجرت در [قرارداد جاری](../architecture/stage-04.md) آمده است.
