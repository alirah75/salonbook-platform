# وضعیت مرحلهٔ ۴

به‌روزرسانی: مرحلهٔ ۵ با تأیید کاربر انجام شد؛ وضعیت جاری در [stage-05-progress.md](stage-05-progress.md) است. موارد زیر سابقهٔ تحویل مرحلهٔ ۴ هستند.

مجوز شروع: درخواست کاربر برای اجرای گام بعد با مصرف کمتر توکن.

قرارداد جاری به درخواست کاربر: ورود با موبایل ایران و رمز، بدون ایمیل؛ OTP بعداً. Session opaque و Tenant از دامنهٔ ثبت‌شده حفظ شده‌اند. مدیریت Tenant در مرحلهٔ ۵.

انجام‌شده: یکسان‌سازی شماره، یکتایی در سالن، ورود و ثبت‌نام موبایلی، حذف API/worker/تنظیمات ایمیل، وضعیت تأیید شماره برای OTP آینده و ابزار اتصال شماره به حساب قدیمی. مهاجرت داده بدون ساخت شماره یا حذف اطلاعات قدیمی است.

نتیجه: ۱۸۸ آزمون موفق؛ Ruff و mypy موفق؛ migration 0005 و اسناد مطابق. ثبت‌نام، ورود، تغییر رمز و خروج با HTTP واقعی بررسی شدند. ایمیل یا پیامک ساخته یا ارسال نمی‌شود.

محل ادامه: [سند تحویل](../architecture/stage-04.md) و [گزارش آزمون](verification-mobile-login.md). مرحلهٔ ۵ فقط پس از تأیید کاربر شروع شود. OTP و بازیابی رمز فراموش‌شده به درخواست کاربر برای بعد باقی مانده‌اند؛ مالکیت شماره هنوز اثبات‌شده نیست. تغییر نقش/شماره زیر قفل User همراه افزایش auth_version و کنترل مجوز در تراکنش Serviceهای تجاری رعایت شود.
