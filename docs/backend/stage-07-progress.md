# نقطهٔ ادامهٔ مرحلهٔ ۷

این سند وضعیت تاریخی پایان مرحلهٔ ۷ است. مرحلهٔ ۸ نیز با درخواست کاربر اجرا شده است؛ وضعیت جاری در [stage-08-progress.md](stage-08-progress.md) قرار دارد.

درخواست «مرحله بعد» در ۲۰۲۶-۱۰-۰۳ مجوز اجرای مرحلهٔ ۷ است. مراحل ۱ تا ۶ تکمیل شده‌اند؛ مرحلهٔ ۸ هنوز مجوز ندارد. ورود فقط موبایل و رمز است؛ ایمیل اضافه نشود و OTP به آینده موکول است.

پیاده‌سازی: محاسبات بازه‌های نیمه‌باز UTC، تقویم هفتگی و استراحت، روز استثنایی، مرخصی/تعطیلی/مسدودی، درخواست و تأیید مرخصی، تنظیمات زمان‌بندی و API عمومی وقت آزاد. برنامهٔ سالن و کارمند الزامی و بدون ساعت بسته است؛ تقویم اختیاری لاین و کارمندـلاین محدودیت اضافه می‌کند. همهٔ تغییرات زیر قفل CalendarControl با کنترل نوبت‌های موجود و rollback اتمی اجرا می‌شوند. مجوزهای جدید با migration 0008 و اجبار ورود مجدد نشست‌های دارای مجوز تغییریافته همراه‌اند.

آزمون‌ها: اجرای کامل ۳۰۶ آزمون در 229.73s موفق شد. پس از اصلاح نهایی دامنهٔ نقش سفارشی و افزودن دو آزمون، هر ۳۲ آزمون زمان‌بندی و migration در 84.50s موفق شدند؛ مجموعه اکنون ۳۰۸ آزمون دارد. Ruff، mypy برای ۱۱۳ فایل، schema docs و lockfile موفق‌اند. گزارش دقیق در [verification-stage-07.md](verification-stage-07.md) و قرارداد در [stage-07.md](../architecture/stage-07.md) ثبت شده است.

مرحلهٔ ۷ کامل است. بررسی HTTP واقعی موفق و مستندات و README به‌روز شده‌اند. پیش‌نمایش تازه روی `http://127.0.0.1:8000/api/v1/docs` با migration 0008 در حال اجراست؛ readiness و مسیرهای جدید بررسی شده‌اند. نمونهٔ موقت قبلی متوقف شد و دیتابیس ماندگار دست‌کاری نشده است.

محل ادامهٔ مرحلهٔ ۸: تابع `scheduling.engine.availability` فقط خواندنی است؛ قبل از درج نوبت باید شرایط زیر قفل اشتراکی CalendarControl دوباره بررسی شوند، Holdهای منقضی با گذار دامنه‌ای منقضی شوند و قفل کارمند، exclusion و idempotency رعایت شوند. ترتیب خدمات و فرمول بافر در سند مرحلهٔ ۷ تعریف شده است. snapshot نوبت‌ها تغییر نکند. مرحلهٔ ۸ هنوز درخواست نشده است.
