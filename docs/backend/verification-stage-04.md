## شواهد امنیتی

- Cookie روی HTTPS دارای Secure، HttpOnly، SameSite و پیشوند __Host- است؛ Session خام در پاسخ JSON یا دیتابیس نیست.
- ثبت‌نام Role و Tenant تزریقی را رد می‌کند؛ حساب جدید فقط Customer همان سالن است.
- پاسخ تکرار ثبت‌نام و بازیابی حساب ناموجود، وجود حساب را در status/body آشکار نمی‌کند. برابری آماری زمان پاسخ زیر بار ادعا نشده است.
- Host ثبت‌نشده، دامنهٔ غیرفعال/تأییدنشده و سالن معلق بسته می‌مانند؛ Headerهای Tenant/Forwarded جای resolver را نمی‌گیرند.
- CSRF پیش از ورود و CSRF نشست، Origin نادرست، Token جعلی/منقضی و فرم به‌جای JSON بررسی شدند.
- مصرف توکن Verify با دو اتصال هم‌زمان دقیقاً یک موفقیت و یک رد داشت؛ هدف اشتباه، Tenant دیگر، انقضا، مصرف مجدد و صدور مجدد نیز آزموده شدند.
- Reset و تغییر رمز، نشست‌های پیشین را رد کردند. تغییر رمز با رمز فعلی اشتباه موفق نشد. Hash قدیمی در ورود موفق ارتقا یافت.
- سقف Rate Limit میان درخواست‌های هم‌زمان مشترک بود و شکست ورود شمارنده را rollback نکرد. IP نیز برای حساب‌های متفاوت محدودیت مشترک داشت.
- نقش جدید نشست قبلی را نامعتبر کرد؛ Line Manager فقط Line مجاز را دید؛ Owner guard و شرط تأیید ایمیل اعمال شدند. بازگرداندن نقش نشست ردشده را دوباره معتبر نکرد.
- صف ایمیل با دو Worker تنها یک Claim فعال داشت. شکست SMTP با کد عمومی و retry ثبت شد؛ Token مصرف‌شده ارسال نشد و payload رمز‌شده پس از پایان کار پاک شد. lease رهاشده با سقف تلاش کنترل شد.
- لاگ و Outbox فاقد رمز و توکن خام بودند. اجرای production روی HTTP، Cookie احراز هویت صادر نکرد.

## بررسی واقعی اجرا

سرور با `scripts.dev --port 8000` اجرا و `scripts.check_auth_preview` از طریق HTTP واقعی به آن متصل شد. مسیر زیر به‌طور کامل موفق بود:

ثبت‌نام → فایل ایمیل محلی → ورود → تأیید ایمیل → Current User تأییدشده → فراموشی رمز → فایل ایمیل Reset → بازنشانی → رد نشست قبلی → ورود با رمز تازه → خروج → رد درخواست بدون نشست.

این بررسی از transport واقعی شبکهٔ محلی استفاده کرد، علاوه بر TestClient. ابزار رمز و Token را چاپ نکرد. فایل‌های ایمیل در backend/.local/mail باقی می‌مانند تا قابل بازبینی باشند؛ هیچ پیام واقعی به خارج ارسال نشد.

argon2-cffi 25.1.0، cryptography 48.0.1 و email-validator 2.3.0. نسخه‌های قبلی FastAPI و PostgreSQL طبق lockfile و image دارای digest ثابت حفظ شده‌اند.

این گزارش آزمون خودکار و جریان محلی را تأیید می‌کند؛ ارسال SMTP واقعی، تحویل به Inbox عمومی، تنظیم DNS، سنجش بار و آزمون نفوذ production در این جلسه انجام نشده‌اند. تنظیمات و قرارداد ادامهٔ کار در [سند مرحلهٔ ۴](../architecture/stage-04.md) ثبت شده است.
