# وضعیت مرحلهٔ ۵

به‌روزرسانی ۲۰۲۶-۱۰-۰۳: مرحلهٔ ۶ با تأیید کاربر تکمیل شد؛ وضعیت جاری در [stage-06-progress.md](stage-06-progress.md) است. موارد زیر سابقهٔ مرحلهٔ ۵ هستند.

مجوز شروع: درخواست صریح کاربر «بریم گام بعدی را پیاده سازی کن» و سپس «ادامه بده».

مرحلهٔ ۵ کامل و بررسی شده است:

- API مدیریت سالن، مشخصات شخصی، کاربران، پروفایل کارکنان، نقش‌ها، مجوزها و انتساب نقش در دامنهٔ سالن/لاین.
- کنترل سقف تفویض، حفظ آخرین مدیر، ابطال نشست‌ها و ثبت تغییرات در Audit همان تراکنش.
- ابزار مستقل ساخت سالن با مدیر اولیه و کنترل دامنه/تعلیق؛ اتصال محدود و جدا از API.
- migration 0006، حفاظت در برابر استفاده از اتصال مدیریتی در API و کنترل دوبارهٔ دامنه داخل تراکنش.
- ۲۲۷ آزمون موفق: اجرای کامل ۲۲۶ آزمون + آزمون الحاقی bootstrap-manager. Ruff، mypy، schema docs و lockfile موفق.
- HTTP واقعی مدیریت سالن/کارمند/نقش و ابطال نشست موفق بود.
- تعیین اولین مدیر سالن قدیمی، فقط توسط ابزار اپراتور و پس از بررسی حساب موجود، اضافه و آزموده شد.

محل ادامه: [سند تحویل](../architecture/stage-05.md) و [گزارش آزمون](verification-stage-05.md). migration جاری 0006 است. API عمومی پلتفرم وجود ندارد؛ `scripts.manage_tenants` از اتصال مستقل استفاده می‌کند. پیش‌نمایش معمول مدیر پیش‌فرض ندارد؛ گزینهٔ `--manager-phone` رمز مدیر را مخفی می‌پرسد.

پیش‌نمایش تازهٔ مرحلهٔ ۵ روی `http://127.0.0.1:8000/api/v1/docs` اجرا شد؛ health/ready و مسیرهای OpenAPI مدیریت تأیید شدند. آزمون واقعی ورود موبایلی نیز روی همین پیش‌نمایش موفق بود. محیط قبلی موقتِ مرحلهٔ ۴ متوقف و محیط موقت تازه ساخته شد؛ دیتابیس ماندگار تغییر نکرد.

قرارداد ورود: موبایل ایران و رمز؛ بدون ایمیل، OTP و بازیابی رمز فراموش‌شده برای بعد. مرحلهٔ ۶ هنوز مجوز شروع ندارد: لاین‌ها، خدمات، EmployeeLine/EmployeeService/LineService. وضعیت User و EmployeeProfile هر دو در قواعد بعدی بررسی شوند. ترتیب قفل lifecycle → management → User → Session و بررسی مجوز داخل تراکنش حفظ شود.
