# وضعیت مرحلهٔ ۶

این سند وضعیت تاریخی پایان مرحلهٔ ۶ است. کاربر مرحلهٔ ۷ را نیز مجاز کرده است؛ وضعیت جاری در [stage-07-progress.md](stage-07-progress.md) ثبت می‌شود.

مجوز شروع: درخواست کاربر «مرحله بعد» در ۲۰۲۶-۱۰-۰۳، پس از تحویل مرحلهٔ ۵.

مرحلهٔ ۶ کامل و بررسی شده: CRUD لاین/خدمت، قیمت و مدت و buffer در LineService، EmployeeLine و EmployeeService با دامنهٔ لاین، حذف نرم کارمند، کاتالوگ عمومی بدون دادهٔ حساب. ساخت/ویرایش/غیرفعال‌سازی کارمند از مسیر کاربران مرحلهٔ ۵ حفظ شده است.

تصمیم‌ها: مجوز جدید `staff.assign` برای مدیر سالن و مدیر لاین؛ تغییر موجودیت مشترک فقط در سطح سالن. ارتباط حذف‌شده با همان شناسه قابل بازاتصال است ولی ارتباط‌های فرزند حذف‌شده خودکار زنده نمی‌شوند. غیرفعال کردن والد ارتباط‌ها را حفظ و از خروجی عمومی پنهان می‌کند.

قفل lifecycle → management برای نوشتن → CalendarControl اشتراکی/انحصاری → User → Session. تغییر کاتالوگ نسخهٔ CalendarControl را افزایش می‌دهد. نوبت AWAITING_PAYMENT یا CONFIRMED که occupied_ends_at آن نگذشته، مانع حذف/غیرفعال کردن منبع مرتبط است. تغییر قیمت/مدت فقط برای نوبت جدید است و snapshotهای قبلی ثابت می‌مانند.

migration جاری 0007؛ ۲۷۳ آزمون در اجرای کامل موفق (173.56s)، Ruff، mypy، schema docs و lockfile موفق. HTTP واقعی از `scripts.check_catalog_preview` موفق بود. قید قیمت رایگان/پولی در API و دیتابیس یکسان است؛ دادهٔ قدیمی ناسازگار مهاجرت را rollback می‌کند و بی‌صدا تغییر نمی‌کند.

محل ادامه: [سند تحویل](../architecture/stage-06.md) و [گزارش آزمون](verification-stage-06.md). ساخت/ویرایش حساب هنوز از users انجام می‌شود؛ employee_id شناسهٔ پروفایل است. ارتباط‌ها با PUT بازاتصال می‌شوند، موجودیت‌های پایه Line/Service از حذف نرم بازگردانی عمومی ندارند. پروفایل کارمند قابل بازگردانی است ولی نقش employee و ارتباط‌های حذف‌شده صریحاً دوباره داده شوند.

پیش‌نمایش تازهٔ مرحلهٔ ۶ روی `http://127.0.0.1:8000/api/v1/docs` اجرا شد؛ readiness، OpenAPI و کاتالوگ عمومی بررسی شدند. آزمون HTTP احراز هویت نیز روی همین سرور موفق بود. محیط موقت مرحلهٔ ۵ متوقف و نمونهٔ موقت تازه ساخته شد؛ دیتابیس ماندگار تغییر نکرد. پیش‌نمایش عادی مدیر پیش‌فرض ندارد؛ گزینهٔ `--manager-phone` رمز مدیر اولیه را مخفی می‌پرسد.

مرحلهٔ ۷ (Scheduling Engine) مجوز شروع ندارد. از `scheduling/coordination.py` برای قفل تقویم استفاده شود. رزرو آینده باید قفل اشتراکی تقویم را قبل از User و قبل از خواندن شرایط بگیرد؛ snapshot قیمت/مدت و exclusion constraint حفظ شوند. آزمون رقابت رزرو/حذف این قرارداد را پوشش می‌دهد. ورود موبایلی و بدون ایمیل حفظ شده؛ OTP بعداً.
